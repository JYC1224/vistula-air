# 首版實作與驗收紀錄

## 依序完成的範圍

1. **素材階段**：先完成八款照片的型號與授權核對、地圖與機場資料、Kenney 音效與字型選用；來源隨遊戲發佈。
2. **MVP 核心**：完成公司、派機、預估與日結、維修停場及委託進度，並建立可獨立驗證的模型。
3. **機隊迭代**：加入八款機型、資料庫、兩機比較、購買與租賃。
4. **情境迭代**：加入六份委託、員工訊息、機庫互動結構圖與跨洲地圖。
5. **體驗迭代**：加入本機存檔、音效設定、快捷鍵、失誤說明與字體／操作位置調整。

## 已驗證

- 模型檢查：派機不得超航程、不得重複占用同一飛機，無效操作不改變原始狀態。
- 保養占用完整營運日，當日完成後於下一天恢復派飛。
- 租賃首期與每日租金分開計算，閒置時仍產生租金。
- 預估與日結使用同一套營收與成本模型。
- 六份委託可在資金與維護條件下全部完成。
- 破損或不完整存檔會回到可用的初始狀態。
- 瀏覽器實際完成 CPH 開航與三個營運日，取得第一份委託獎勵。
- 瀏覽器比較 E190 與 737-800 的載客率和成本差異；比較 A320ceo 與 neo 的相同機身長度、不同引擎世代。
- 瀏覽器租賃 E195-E2，確認機隊、資金與日租金更新。
- 瀏覽器安排保養，確認停場日取消執飛與保養完成提示。
- 瀏覽器操作機體熱點與音效設定；修正熱點按下時位移造成點擊失效的問題。
- 重新載入後保留公司進度，並回到目前進行中的委託。

## 本版模型界線

目前每架飛機同時服務一條航線，班次為每日往返。市場需求、定價、購租與維護數值用於教學與遊戲平衡；沒有模擬真實簽派、燃油政策、時區班表與維修規章。

機型資料庫與結構圖提供查閱和應用支援。實際的學習保留與遷移，仍需要未見過的情境、玩家解釋與延後評量，不能只用通關或查閱次數判定。

下一輪應依玩家試玩回饋，先調整工作節奏、資訊量與取捨，再擴充更多近二十年的常見機型與細分配置。
